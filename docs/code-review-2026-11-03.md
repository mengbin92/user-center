# 用户中心代码审查与修复记录

审查于 2026-11-02 开始，2026-11-03 完成。依据桌面上的《用户中心独立项目设计文档.md》、仓库 `AGENTS.md` 以及 `docs/` 中的架构、API、安全、数据模型、前端、迁移和运维约定。

本轮审查覆盖 domain、biz、data、service、HTTP/gRPC、React SPA、离线命令、MySQL 迁移及 Docker 部署。下列为已确认并修复的问题；安全行为使用服务端拒绝用例验证。

## 主要发现与修复

| 优先级 | 原问题及影响 | 修复与验证 |
|---|---|---|
| P1 | self 与 user_ids 求交可扩大为其他用户；继承角色按错误的角色 ID 激活，停用中间角色仍可能继承权限 | 按 actor 求交，沿有效继承路径解析，以原分配角色控制 allow 激活；deny 不受取消激活影响；领域与 HTTP 越权拒绝测试 |
| P1 | 创建用户可夹带高权限角色；角色复制、继承、分配可间接获得 root；普通管理员可变更 root 凭据 | 创建仅授默认 member；额外角色走独立分配；初始密码另需凭据权限与 Step-up；root 的角色和敏感目标受到服务端保护 |
| P1 | 仅拥有分配操作权限也可授予超出自身能力的角色；失效的管理角色仍可匹配委派 | 分离操作权限与可授予权限，检查继承、boundary、GrantCeiling、目标范围和有效期；使用当前有效分配核验委派 |
| P1 | 批量授权未完整执行 Step-up、容量、有效期和互斥约束；并发策略写可能使用旧授权 | 策略锁内重新授权与校验，任一目标失败整批回滚；补齐 reason、policy revision 和目标 revision，拒绝省略或陈旧版本 |
| P1 | 密码重置写死凭据 revision=1，改密后无法恢复；验证码尝试数未持久化，完成记录未拒绝重放 | 使用当前凭据 CAS；原子更新尝试次数；数据库唯一完成记录拒绝再次消费；HTTP 重置、锁定和重放测试 |
| P1 | TOTP、恢复码、MFA 状态和会话角色无完整并发保护，可重复消费或覆盖新状态 | MFA CAS、保留清空后的 revision、防 ABA；会话角色 CAS 与事务；并发仅一个请求成功 |

| P1 | 列表先分页后 deny，泄漏 total 且游标可能不前进；概览会话/登录数为全局值；邮箱搜索可推断被隐藏字段 | allow/deny 在 SQL 计数与分页前生效；全部统计使用可见用户集合；邮箱检索另受联系方式权限控制；同时修复 LIKE 转义的 SQLite/MySQL 差异 |

| P2 | 权限、约束和菜单更新错误校验未传入的不可变字段；约束删除忽略版本；模拟未构造假设分配且污染 before | 事务内读取不可变字段、目标 CAS；复用真实授权解析模拟假设分配，不持久化，分别验证新增 allow 和移除 deny |

## 契约及升级注意事项

- 已通过 `make api`、`make wire` 与前端类型生成更新生成物，未手工编辑生成代码。
- 管理客户端需要发送新增的 `expected_policy_revision`、目标 `expected_revision` 和非空 `reason`；前端已同步。
- 内部接入改用数据库管理的客户端凭据；旧 `USER_CENTER_INTEGRATION_TOKEN` 不再授权。`RevokeSession` 需要 `session_token` 用户证明。
- HTTP/事件的 ID 和 64 位 revision/计数使用十进制字符串。未列入 proto 的字段不再被静默忽略。
- 老导出制品没有新授权快照，或权限/会话角色已变化时，需要重新导出。
- 导入的治理角色为待确认候选，必须经明确范围和独立授权流程重新授予；不从旧 role code 推导全量权限。
- 生产必须使用合格的独立密钥和可达 Redis；订阅 Webhook 需配置签名密钥。开发 console 邮件不再输出验证码，收信测试使用本地 SMTP。
