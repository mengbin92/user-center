# v0.13.0 · 2026-11-19

上一版为 [v0.12.1](./release-v0.12.1.md)。本版按 **MINOR** 发布，新增无密码 Passkey 登录 API 和界面入口，并纳入全仓审查修复。

## 变更与影响面

| 优先级 | 影响面 | 根因与修复 |
|---|---|---|
| P0 | MySQL 租户搬迁 | `tenant-migrate -purge` 原先使用目标库表名执行清理，可能删除刚复制的数据。现在按组织在单个事务内复制并核对行数和内容，仅清理已校验的平台副本。发现目标不一致时回滚本组织。重复执行会保留已完成搬迁的租户数据。 |
| P1 | 账号、认证与会话 | 新增 `POST /api/v1/auth/passkey/login:begin` 和 `POST /api/v1/auth/passkey/login:complete`。公开挑战使用可发现凭据，省略账号凭据 ID，服务端强制设备验证。已有 TOTP 时继续第二步。修复自助和管理员密码重置，挑战绑定邮箱和身份版本。OAuth 登录遵循提供方启停策略及已配置的第二因素。 |
| P1 | SCIM、OIDC 与 IAM | SCIM 凭据只可维护本组织供给数据，最后一位组织 owner 受保护。OIDC 撤销同意会同步撤销未兑换授权码和刷新令牌。IAM 处理局部 `deny`，组织角色变更校验操作者授权上限。 |
| P2 | 目录同步与并发 | 部分失败的目录同步保留并重试游标，隔离租户的邀请接受和目录历史在本组织内处理。修复 IAM 单连接卡死和 Outbox 过期执行结果覆盖。 |
| P2 | 数据清理、运维与前端 | 归档清理覆盖密码历史，MySQL 平台迁移按库串行，已有租户 schema 可补齐缺失列。健康探针独立于浏览器 Cookie。前端取消会话切换后仍在等待 CSRF 的旧写请求。 |

## 兼容性与升级步骤

1. 备份平台库和已启用隔离的租户库。从 v0.12.1 升级无需新增平台迁移文件。更早版本先用本版 `cmd/migrate` 补齐已有迁移至 `017`。
2. 已使用 MySQL 租户隔离的实例需在维护窗口停止写入。用本版 `cmd/tenant-schema` 补齐旧租户表缺少的 IAM 上下文和审计组织列，保持原 schema 前缀。新启用隔离时先预演、复制并核对，再按需清理平台副本。曾运行旧版本 `-purge` 的实例应先确认平台副本和备份，再执行恢复或搬迁。[租户迁移手册](../tenancy.md#4-启用与-cutover)
3. 已启用 SQLite 文件隔离的开发实例先停服务、备份并核对旧租户文件归属，再移入 `<平台数据库路径>.tenants/`。[SQLite 租户文件说明](../tenancy.md#1-形态)
4. SCIM 和目录源可在创建账号时写入 `userName`、`displayName` 和 `emails`。既有账号的共享资料由平台账号流程维护。SCIM 可原样回传当前值，提交变化时返回 `400 mutability`。[SCIM 供给规则](../scim.md)
5. 部署后检查 `/healthz`、`/readyz` 和登录。升级前未使用的密码重置及邮箱变更挑战需重新申请。OIDC 已签发的访问令牌继续有效至到期。裸机示例关闭转发头信任，Compose 配置显式启用。只有后端仅由受信代理访问时才开启 `TRUST_PROXY_HEADERS`。[运维手册](../operations.md#4-反向代理)

如需回退隔离切换，应先确认平台副本是否已清理，并核对切换以来的写入。已执行 `-purge` 的组织需从备份恢复平台副本。[回滚说明](../tenancy.md#7-运维前置)
