# v0.5.2 · 2026-11-04

上一版：[v0.5.1](./release-v0.5.1.md)

本版为全项目代码审查的修复批次，无数据库迁移，无配置变更。

## 安全与隔离

- **改密门禁覆盖组织路由**：`requiresAuth` 此前只识别 `/api/v1/me` 与 `/api/v1/admin`，
  `/api/v1/orgs` 的改密判断位于不可达分支。初始密码账号在改密前即可创建、读取组织。
  现在认证路径与改密门禁共用同一份路径表。
- **租户侧账号枚举**：添加成员时「账号不存在」与「账号被禁用」返回不同错误，租户管理员
  可借此探测全平台账号。两种失败现在返回完全一致的响应。
- **Webhook 回调限制**：公网回调必须 `https`；链路本地（含云元数据地址）与未指定地址
  一律拒绝。管理员面 SSRF 面收敛。
- **gRPC 默认拒绝**：拦截器不再放行非 `IntegrationService` 方法。

## 正确性与并发

- **最后 owner 保护**：计数移入事务并加行锁（MySQL `FOR UPDATE`），并发降级/移除不会再
  把组织变成零 owner。
- **角色分配上限**：重复授权与 `max_members` 检查移入事务并锁角色行，并发分配不再超限。
- **归档角色**：`PutRoleGrants` 补齐归档状态校验，归档后不可再改权限。
- **组织懒回填**：平台管理员访问旧组织时也会补齐内置角色，不再返回空列表。

## 性能

- **用户列表查询放大**：此前每行调用两次授权决策，每次重载全部角色/Grant/继承/分配/约束，
  单行约 16 条查询（20 行约 320 条）。现在整页只加载一次策略事实，角色与 MFA 状态各一次
  批量查询。
- **单角色读取**：`GetRole` 不再全量加载角色表后线性查找，改为按 id 读取角色及其
  Grant/继承。

## 契约与审计

- **`reason` 强制**：管理写操作必须携带非空理由（≤512 字符），不再自动填充默认值，
  与 `docs/api.md` 的约定一致。
- **`authorization:explain`**：`resource_id` 非空时返回 400。资源级事实属于资源 owner，
  平台接口不再返回看似权威但不完整的结论；SPA 已移除该输入项。
- **迁移可恢复**：MySQL DDL 会隐式提交，文件级事务无法回滚。迁移进度改为按语句记录，
  失败后重跑可从最后成功的语句继续。

## 验证

- `go vet ./...`、`go test ./...`、`go test -race ./domain/... ./internal/biz/ ./internal/data/ ./internal/server/` 全绿。
- 前端 `npm test`（57 项）与 `npm run build` 通过。
- 新增回归：改密门禁覆盖组织路由、`reason` 必填、归档角色只读、账号枚举统一响应、
  资源级解释拒绝、Webhook 回调校验。
- MySQL 迁移测试（`USER_CENTER_MYSQL_TEST_DSN`）覆盖 006 的列与索引。

## 兼容性

- 管理写请求缺少 `reason` 现在返回 400 `VALIDATION_FAILED`；按文档实现的老客户端不受影响。
- `authorization:explain` 传 `resource_id` 由「静默忽略」改为 400。
- 其余接口、数据结构与配置不变，可直接替换镜像。

## 已知保留项

- 平台授权决策仍会在每次请求加载一次平台角色与约束（3 条查询）。基于策略版本的进程内缓存
  曾在实现中尝试，但直接写仓储的路径（导入工具、测试）不会推进策略版本，存在读到旧策略的
  风险，故未启用；后续需先保证所有写入都经用例层。
- 前端主包仍超过 500 kB 的构建告警，需按路由拆包，属于构建优化而非缺陷。
